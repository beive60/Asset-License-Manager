## 1. プロジェクト概要と制約

* **目的**: 動画編集者向けの素材ライセンス（URL、クレジット表記）管理およびYouTube概要欄テキスト自動生成ツール。
* **実行環境**: Windows 11 / Python 3.11 / PySide6（GUI）
* **制約**:
  * 外部API通信不可。ローカルのファイル走査とJSON読み書きのみで完結させる。
  * バックグラウンドの常駐プロセスやDB（SQLite等）は使用せず、独立したローカルアプリとして構成する。

---

## 2. ディレクトリと対象ファイル仕様

* **ルートフォルダの指定**:
  * ユーザーがGUI上のボタンから素材ルートフォルダを選択する。
  * 選択されたパスはヘッダー領域のラベルに表示する。
  * 選択されたフォルダパスは `QSettings` を利用してOS側（レジストリ等）に保存し、次回アプリケーション起動時に自動で復元し、初期パスとして設定・スキャンを実行する。
* **必須ディレクトリ構造**（スキャン実行時に存在しなければ `os.makedirs` で自動生成すること）:
  * `audio/bgm`, `audio/se`
  * `picture/background`, `picture/character`, `picture/item`
  * `video/background`, `video/effect`, `video/transition`
* **スキャン対象拡張子**（大文字小文字は区別しない。これ以外の拡張子は無視すること）:
  * **audio**: `.mp3`, `.wav`, `.ogg`, `.flac`, `.aac`, `.m4a`
  * **picture**: `.jpg`, `.jpeg`, `.png`, `.webp`, `.gif`, `.bmp`, `.tif`, `.tiff`
  * **video**: `.mp4`, `.mov`, `.webm`, `.mkv`, `.avi`, `.m4v`, `.wmv`, `.flv`, `.mpeg`, `.mpg`

## 3. データ構造定義 (JSON Schema)

### 3.1 保存場所

各JSONマスターデータは、**ユーザーが指定した素材ルートフォルダの直下**（または `.license_manager/` などの専用隠しフォルダ内）に保存・読み込みを行う。

### 3.2 ファイル分割

データはジャンルごとに以下の3ファイルに分割して保存する（存在しない場合は初期化して自動生成する）。

* `audio-assets-license.json`
* `picture-assets-license.json`
* `video-assets-license.json`

### 3.3 データスキーマ

JSONのルート構造は、素材ルートディレクトリからの「正規化された相対パス（スラッシュ区切り）」をキーとした単一階層の辞書型とする。

```json
{
  "audio/bgm/epic_battle_01.mp3": {
    "url": "https://example.com/audio1",
    "attribution": "Epic Battle by Author A",
    "category": "audio/bgm"
  }
}
```

## 4. コアロジック要件

### 4.1 同期と状態検出

実ファイルのスキャン結果とJSONのキーを突き合わせ、以下のステータスを判定する。

* **Missing（新規未登録）**: 実ファイルが存在するが、JSONにキーが存在しない、またはURLとAttributionの両方が空欄のデータ。
* **Filled（登録済み）**: 実ファイルが存在し、JSONにURLまたはAttributionが入力されているデータ。
* **File not found（実体消失）**: JSONにキーが存在するが、実ファイルが見つからないデータ。

### 4.2 File not found の管理と削除ロジック

ファイル名編集による二重検知やキー衝突リスクを防止するため、UI上でのファイル名直接編集は行わない。

* **手動行削除**:
  * データグリッド上の任意の行で右クリックした際、コンテキストメニュー「この項目を削除（JSONから除外）」を表示し、選択された行をUIおよび内部データから削除する。
* **一括削除（Prune）**:
  * ツールバーの「File not foundを一括削除」ボタン押下により、ステータスが `File not found` となっている全レコードをUIおよび内部メモリから一括パージする。
  * 削除実行後はDirtyフラグ（未保存変更あり）をTrueにする。

### 4.3 テキスト整形 (Format)

* **重複排除**: `attribution` が完全に一致する素材は1つにまとめる。
* **Markdownサニタイズ**: `[任意のテキスト](URL)` の表記は `任意のテキスト (URL)` に置換する。
* **改行文字のパース**: ユーザーがセルに文字として `\n`（バックスラッシュ+n）と打ち込んだ場合、テキスト出力時に実際の改行として解釈・置換する。
* **改行修復**: 連続する空行（`\n\n\n` 等）は最大1行の空行（`\n\n`）に圧縮する。
* **ncID抽出**: `url` および `attribution` の文字列全体から正規表現 `nc\d+` を抽出し、重複を排除して半角スペース区切りで出力する。

### 4.4 概要欄テキスト生成機能

* **対象選定**:
  * データグリッドの **Check Box列がON（Checked）になっている行のみ** を対象とする。
* **未入力素材の自動分離**:
  * チェックされた行の中で「URLとAttributionの両方が空欄」の素材は、概要欄クレジット本文には出力せず、「出展確認素材（要確認リスト）」セクションにファイルパス一覧として振り分け出力する。
* **出力フォーマット仕様**:

  ```text
  【クレジット表記】
  {整形済みAttribution / URLの一覧}

  【ニコニ・コモンズ 親作品登録用ID】
  {スペース区切りのncID一覧}

  【出展確認素材（要確認リスト）】
  {URL/Attributionが未記入の素材ファイルパス一覧}
  ```

* **出力・保存方式**:
  * 「テキスト生成」ボタン押下時、**OS標準のファイル保存ダイアログ（`QFileDialog.getSaveFileName`）** を表示する。
  * デフォルトファイル名候補: `概要欄コピペ用_クレジット一覧.txt`
  * デフォルトパス: 選択中の素材ルートディレクトリ直下
  * エンコード: **UTF-8（BOMなし）**

### 4.5 JSONへの保存

* UIで編集・削除された最新データを各ジャンル対応のJSONファイル（素材ルート直下）に上書き保存する。
* 保存完了時、DirtyフラグをFalseにリセットする。

### 4.6 ステータスの動的更新

* ユーザーが `URL` または `Attribution` 列を編集し、フォーカスが外れた（または編集が確定した）タイミングで、内容が入力されていれば行のStatusを自動的に `Missing` から `Filled` へ更新し、文字色（警告色）を通常色へ戻す。
* 同時にDirtyフラグをTrueに設定する。

### 4.7 算出プロパティの相互変換

* JSON内部の `category`（例: `"audio/bgm"`）は、UI表示時にスラッシュで分割して `Genre: audio`, `Category: bgm` 列にバインドする。
* ファイルパスキー（例: `"audio/bgm/track1.mp3"`）からファイル名部分（`track1.mp3`）を抽出して `File Name` 列に表示する。

## 5. UI仕様 (PySide6)

メイン画面は `QTableWidget`（または `QTableView`）を用いたデータグリッドを中心に配置する。

**リサイズ追従** メインウィンドウのリサイズ時、TableWidgetがウィンドウサイズに追従して自動的に拡大・縮小されるよう適切なレイアウト（`QVBoxLayout`等）に組み込むこと。

### 5.1 上部ツールバー / コントロール

1. **素材フォルダ選択 ボタン**:
   * ディレクトリ選択ダイアログを表示し、素材ルートフォルダを設定する。
   * 選択後、パス表示ラベルを更新し、自動で「同期」処理を実行する。
2. **同期 ボタン**:
   * 実ファイル走査とJSON突き合わせを行い、グリッドを最新化する。
3. **File not foundを一括削除 ボタン**:
   * グリッド内の `File not found` 行をすべて削除し、DirtyフラグをTrueにする。
4. **保存 ボタン**:
   * 現在のグリッドの内容をJSONマスターに書き出す。
5. **テキスト生成 ボタン**:
   * チェックされた行を対象に、ファイル保存ダイアログ経由で概要欄テキストを書き出す。

### 5.2 データグリッド仕様

* **列定義**:
  1. `Check Box`: 一括テキスト生成の対象フラグ。
  2. `Status`: `Missing`, `Filled`, `File not found` を表示。
  3. `Genre`: `audio`, `picture`, `video`
  4. `Category`: `bgm`, `se`, `background`, `character`, `item`, `effect`, `transition`
  5. `File Name`: 相対パス末尾のファイル名（閲覧専用）。
  6. `URL`: 素材配布元URL（**編集可能**）。
  7. `Attribution`: 著作権・クレジット表記（**編集可能**）。
* **ヘッダー機能**:
  * **【UX改善: ヘッダー表示】** Check Box列のヘッダーテキストは空文字（`""`）とし、クリックで「全選択 / 全解除」をトグルする機能を実装するか、あるいはヘッダーテキストを「選択」とする。
* **表示スタイルとツールチップ**:
  * `Status` が `Missing` の行: 文字色または背景色を赤系（警告色）にする。
  * `Status` が `File not found` の行: 文字色をグレーアウトまたは打ち消し線スタイルにし、実体が存在しないことを明示する。
  * 長い文字列が見切れないよう、`URL` と `Attribution` 列の各セルには `setToolTip` で内容全文を表示させる。

* **セル編集権限とペースト挙動**:
  * `URL` 列および `Attribution` 列のみダブルクリック等で編集可能（Editable）とする。
  * `File Name`, `Genre`, `Category`, `Status` 列は読み取り専用（ReadOnly）とする。
  * `QTableWidget` の `keyPressEvent` をオーバーライドし、Excelライクなペースト（Ctrl+V）を実装する。
    * **起点セル依存**: ペースト先は、現在選択されている範囲の起点（左上）のセルの列を基準とする（ダイアログ等での列選択UIは設けない）。
    * **スプレッドシート対応**: クリップボードのTSV（タブ区切りテキスト）を解析し、2カラムの場合は起点セルから右方向へ展開して貼り付ける。
    * **リピート適用（一括反映）**: クリップボードの内容が「1行分」であり、かつUI上で「複数行」が選択されている場合、その1行分のデータを対象の全選択行に対して繰り返しペーストする。

* **コンテキストメニュー（右クリック）**:
  * 任意の行で右クリック時、「この項目を削除（JSONから除外）」メニューを表示し、選択行を削除可能とする。

## 6. 終了フローとDirtyフラグ管理

1. **Dirtyフラグの管理**:
   * アプリケーション内部に「未保存の変更が存在するか」を表す `is_dirty`（Boolean）を保持する。
   * セル編集、複数セル一括ペースト、右クリック行削除、一括削除ボタン押下などの操作が行われた際に `True` に設定する。
   * 「保存」ボタン押下、または同期直後のクリーンな状態では `False` とする。
2. **終了時（ウィンドウの×ボタン押下時）の挙動**:
   * **`is_dirty == False` の場合**:
     * ダイアログを出さず、即座にアプリケーションを終了する。
   * **`is_dirty == True` の場合**:
     * 確認ダイアログ（「未保存の変更があります。終了前に保存しますか？」）を表示する。
     * 選択肢:
       * **「はい」**: JSONマスターへ変更内容を書き込んだ後、アプリケーションを終了する。
       * **「いいえ」**: 保存を行わずにそのまま終了する。
       * **「キャンセル」**: 終了処理を中断し、編集画面に復帰する。
